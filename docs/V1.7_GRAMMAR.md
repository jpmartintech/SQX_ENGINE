# V1.7 — Grammar expansion

V1.7 expands the representable search space. It does not change the 70/15/15 split,
Validation/OOS gates, execution model, discovery fitness, funnel thresholds or
portfolio selection. The V1.6 control remains 250K unique → 432 Development
candidates → 193 Validation passes → 2 TRUE OOS passes. None of those two OOS
strategies was inspected to set the grammar. No V1.7 production OOS was opened.

## Versioned canonical definitions

New configurations explicitly set:

```yaml
strategy:
  grammar_version: v1.7
  min_predicates: 1
  max_predicates: 4
```

Unversioned historical definitions remain `legacy`: byte-identical JSON and
hashes are preserved. Legacy configs, numeric feature semantics and generator
random trajectories stay unchanged. V1.7 canonicalizes unordered AND/OR
predicates, removes duplicate predicates, normalizes numeric threshold types and
normalizes single-predicate logic to AND. `EMA200 > EMA20` becomes
`EMA20 < EMA200`; equal-period pairs are rejected. Feature names encode every
indicator parameter, including fractal depth, and the grammar version is included
in canonical JSON. It is intentionally a new hash namespace; historical hashes
are not rewritten. Arbitrary Boolean equivalence/tautology elimination is outside
scope.

## Families and fixed grids

| Family | Variants | Definition |
|---|---:|---|
| Trend | 78 | close/EMA, ordered EMA pairs, EMA slope, prior-window breakouts |
| Momentum | 60 | RSI, fractional ROC, Williams %R |
| Volatility | 16 | normalized ATR regime, Bollinger position, BB/Keltner compression |
| Structure | 24 | confirmed fractal events, last HH/HL/LH/LL, swing breakouts |

- EMA: 10, 20, 50, 100, 200; slope lags 1, 3, 6, 12. Slope `>`/`<` zero
  exposes semantic names `EMA_SLOPE_UP`/`EMA_SLOPE_DOWN`.
- Prior high/low breakout windows: 10, 20, 50, 100, **excluding signal bar**.
- RSI(14): 25, 30, 35, 40, 50, 60, 65, 70, 75, preserving the source formula.
- ROC: `close[t]/close[t-N]-1`, N=4,8,16,32; thresholds −0.005, 0, +0.005
  (fractional returns: ±0.5%).
- Williams %R: N=7,14,28; thresholds −80, −50, −20. Current closed bar included;
  zero range is NaN and cannot trigger a predicate.
- ATR regime: simple rolling ATR(14 or 28)/close, divided by its prior-only
  50-bar mean, minus one; comparisons against zero. Stops keep ATR(14).
- Bollinger: simple mean, population standard deviation (`ddof=0`), N=20 or 50,
  width 2.0; close above upper, below lower, above/below middle.
- Keltner: EMA(N) ± 1.5 × simple ATR(N), N=20 or 50. Compression=+1 only when
  both Bollinger bands are strictly inside; expansion=−1 only when both are
  strictly outside. Mixed/equal boundaries are 0, distinct from either event.
- Fractal depths: 2,3,5; strict unique extrema, with both high and low events.
  Equal-height/equal-low ties do not produce fractals.

EMA uses `adjust=False`, with `min_periods=N`. All rolling indicators require full
windows. Undefined features are NaN; numeric predicates always mask nonfinite
values. AND/OR combine these valid masks, with the existing finite-ATR entry guard.
Features are computed once per dataset/split, never inside the strategy loop.

## Structure event timing

A strict pivot at p becomes available only at **p+d**, after d right-hand bars
close. Nothing is backfilled to p. Confirmed highs compare against the previous
confirmed high (HH or LH); confirmed lows compare against the previous low (HL or
LL). Equal successive swing prices do not change the last structural event.
`LAST_STRUCTURE` persists the latest classified event. Initial state is neutral.

If an outside pivot simultaneously confirms a high and a low, there is no unique
ordering of the two events: the state becomes explicitly neutral (0), while both
swing prices update. This avoids inventing a bullish/bearish priority.

A structure breakout compares current close with the most recent swing confirmed
**strictly before the signal bar**. Confirmation at t is eligible for breakout
comparison at t+1. All strategies still execute on the next bar through the
unchanged simulator. Retests, ML, FTMO and portfolio optimization are out of scope.

## Generation, caching and numeric execution

Random immigrants first choose a family uniformly, then one predicate uniformly
within that family. Multi-family strategies are permitted, not required. Genetic
Scale retains bounded populations, tournament selection, immutable crossover and
mutation with novelty retries. V1.7 crossover samples unique parent predicates;
mutation can replace, add or remove a predicate within configured bounds. Exits
use the existing Scale domain: stop ATR={1,1.5,2,2.5}, target ATR={1.5,2,3,4},
time exit={24,48,72,96}. No grid is selected using Validation/OOS.

`FastEvaluator.numeric_predicates` lowers predicates into feature-column integer,
operator integer and numeric threshold. The new Numba predicate kernel handles
`>`, `<`, `==`; no Python dispatch occurs per bar. The resulting masks use
`PredicateCache`; strategy masks and evaluations retain bounded caches. The
backtest kernel itself is unchanged. Python and Numba consume identical feature
arrays. V1.7 configs bound caches at 512 entries rather than the historical 8192
entries, reducing peak memory; this is an execution setting, not a fitness change.

The finite catalog has 178 predicates, 64 exit variants, two directions and
unordered compositions of 1–4 distinct predicates. Including both logics for
counts >1 gives an upper bound of **10,591,415,808 syntactic definitions**. It
includes contradictory/tautological and behaviorally equivalent combinations;
it is not a claim that every definition yields a unique tradable behavior.

## Family telemetry and isolation

Reports group by the exact family combination, ordered Trend, Momentum,
Volatility, Structure. `GENERATED` counts unique evaluated definitions, while
`PROPOSED` counts outer generator proposals including external duplicates. Internal
novelty retry counts are separate. BASIC, STABILITY, PLATEAU, COST, EXECUTION and
DIVERSITY count pass-throughs; absent stage keys mean zero. Single/multi-family
counts sum to unique strategies. Family labels never enter fitness or gates.

Checkpoint state preserves family counters and V1.7 grammar/composition metadata.
Cross-grammar resume is rejected. Existing Development provenance and context
checks stay active. Tests compare both generator resume and a real interrupted
factory resume against uninterrupted execution, including all definitions,
metrics, family counters and final selections.

Validation derives the feature grammar from verified source configuration and
checks each candidate's grammar version. It reports Development candidates,
Validation passes and OOS passes by family combination. OOS only receives
Validation survivors. Both stages retain min_trades=20, PF>=1, expectancy>=0,
Sharpe>=0, and degradation remains diagnostic only. Family telemetry was verified
using synthetic runs without evaluating the V1.7 benchmark candidates on holdout.

## V1.6 output-path correction

The canonical interface is `summary_path` and `csv_path`. Deprecated
`summary_json` and `final_candidates_csv` are accepted **only as migration aliases**
and emit `FutureWarning`. Simultaneous keys resolving to different paths fail
before any database/file output. Identical duplicates emit a warning and collapse
to the canonical key. Missing paths fail explicitly. Regression tests exercise
nested custom destinations, aliases and conflicts.

The historical TRUE OOS config contained canonical paths to the old generic
reports plus aliases pointing to the intended clean reports. V1.6 silently ignored
the aliases; V1.7 rejects that conflict. That historical config/results are kept
as evidence. New V1.7 configs contain only the canonical interface. Do not rerun a
historical validation config into its existing results database merely to recover
exports: that database is protected. The fix does not append to historical runs.

## Reproduction and bounded benchmarks

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/benchmark_grammar.py configs/eurusd_h1_grammar_v17_smoke.yaml --output runs/reports/v17/smoke.json
.venv/bin/python scripts/benchmark_grammar.py configs/eurusd_h1_grammar_v17_1k.yaml --output runs/reports/v17/1k.json
.venv/bin/python scripts/benchmark_grammar.py configs/eurusd_h1_grammar_v17_10k.yaml --output runs/reports/v17/10k.json
.venv/bin/python scripts/benchmark_grammar.py configs/eurusd_h1_grammar_v17_50k.yaml --output runs/reports/v17/50k.json
```

These configs require fresh output databases, or use the ordinary CLI with
`--resume` to read/continue an existing checkpoint. The benchmark driver refuses
more than 50K and writes the search-space audit before discovery. No 250K or 1M
V1.7 run was launched. `eurusd_h1_grammar_v17_250k_clean.yaml` and a separate
validation template are prepared for the next authorized experiment. The latter
requires the actual completed source run ID.

Benchmark reports record factory runtime, full wall time including checkpoint,
throughput, current and peak RSS, duplicates, attempts/unique, component timings,
family distribution and every funnel count. Baseline runs use an archived V1.6
source tree, the same Development data, seed and gates, and separate V1.7 paths.
There are no repeated statistical timing trials; compare timings as local
measurements, not a universal speed guarantee. Historical artifact SHA256 checks
are saved separately. The two already-modified V1.6 reports found at session start
were preserved byte-for-byte.
