## Performance comparison

| Run | V1.6 seconds | V1.7 seconds | V1.6 strategies/s | V1.7 strategies/s | Runtime change |
|---|---:|---:|---:|---:|---:|
| 1k | 2.553 | 3.623 | 391.66 | 276.00 | +41.90% |
| 10k | 20.019 | 17.901 | 499.53 | 558.61 | -10.58% |
| 50k | 112.549 | 117.044 | 444.25 | 427.19 | +3.99% |

50K peak RSS: V1.6 3480.66 MiB; V1.7 2705.56 MiB.

Baseline uses archived v1.6 code, seed 1301 and identical data/split/gates. V1.7 expands from 1–2 to 1–4 predicates and uses bounded 512-entry caches (V1.6: 8192). Single local measurements, including startup; no statistical timing claim. The 1K run has more funnel work (139 Basic passes versus 4 in V1.6). At 50K, wall time rises 4.0% and peak memory falls about 22.3%; no severe regression.

At 50K the largest measured component is FastEvaluator (44.520 s), followed by funnel (28.032 s), diversity (22.694 s) and generation/feedback (10.558 s). All grammar features cost 0.284 s once. Rich survivor equity curves account for substantial memory; diversity compares more surviving definitions. No gates were adjusted to reduce workload.
