# SQX_ENGINE V1.4 — Numba performance core

V1.4 keeps the V1.3 strategy grammar, Genetic trajectory, causal execution
rules, funnel thresholds and portfolio selection unchanged. It adds a numeric
Numba simulation layer behind the existing `FastEvaluator` API.

## Engines

```bash
# Automatic selection: Numba when installed, Python fallback otherwise
sqx run configs/eurusd_h1_1k.yaml --engine auto --workers 1

# Explicit correctness/debug path
sqx run configs/eurusd_h1_1k.yaml --engine python --workers 1

# Explicit accelerated path
sqx run configs/eurusd_h1_1k.yaml --engine numba --workers 1
```

The Python evaluator remains the readable fallback and reference comparison
path. Numba kernels operate on NumPy arrays and preserve the existing
next-bar entry, gap, intrabar SL/TP priority, time-exit and cost semantics.
Aggregate calls use the same numeric trade/equity arrays and NumPy reductions
as the Python path so tiny floating-point reduction differences cannot change
the Genetic trajectory.

## Ryzen run

```bash
git checkout v1.4
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
pytest -q

time sqx run configs/eurusd_h1_1k.yaml --workers 1 --engine numba
time sqx run configs/eurusd_h1_1k.yaml --workers 2 --engine numba
```

Choose the worker count from a warm benchmark. On the xauserver benchmark,
one worker was faster than two because the Genetic coordinator remains
serial and multiprocessing adds overhead. The 250K configuration is prepared
for the Ryzen machine and is intentionally not executed in this release on
xauserver:

```bash
time sqx run configs/eurusd_h1_250k.yaml --workers <BEST> --engine numba
```

## Checkpoint/resume

Checkpoints include the Genetic state, RNG state, canonical hashes, candidate
records and the completed result. A completed checkpoint is idempotent when
resumed; an interrupted `RUNNING` checkpoint continues from its saved
evaluation boundary.

## Reproducibility gate

Golden 1K must retain the V1.3 values and portfolio IDs. Any mismatch is a
correctness failure, not an acceptable optimization trade-off. Benchmark
artifacts are written under `runs/benchmarks/` and are intentionally ignored
by Git.
