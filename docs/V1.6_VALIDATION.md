# SQX_ENGINE V1.6 — VALIDATION / OOS FACTORY

V1.6 evaluates existing canonical strategy definitions. The validation module does
not import generators or the discovery funnel: it never creates neighbors, mutates,
optimizes or feeds Validation/OOS fitness back into discovery.

## Retrospective evaluation

```bash
.venv/bin/python -m sqx_engine.cli validate configs/eurusd_h1_v16_validation.yaml
.venv/bin/python -m pytest -q
```

Inputs are opened read-only. Source integrity, run ownership, canonical hashes,
configuration hash and dataset SHA256 are verified. V1.5's CLI `--engine numba`
override is explicit in the validation YAML; its effective configuration hash
matches the database. Multi-run legacy databases are rejected because their global
strategy table cannot reliably establish per-run ownership.

The historical 250K discovery used all 143,197 bars for genetic feedback and the
quality funnel. It is **RETROSPECTIVE_SPLIT_TEST**, never unseen OOS. Re-evaluation
of all 231 candidates on the original full dataset reproduced all seven stored
metrics (relative tolerance 1e-10, absolute tolerance 1e-12). Historical SQLite and
checkpoint SHA256 values were unchanged.

Split sizes use floor(N * development), floor(N * validation), with the remainder
assigned to OOS. The partition rejects unordered/duplicate/invalid timestamps;
no rows are sorted or silently dropped. Features are computed independently in
each partition, including its own warmup. Positions cannot cross split boundaries.
Execution uses the same FastEvaluator/Numba implementation, spread, slippage,
next-bar entry, final-bar liquidation and individual strategy metrics as discovery.
Development metrics are recalculated on Development, not taken from the historical
full-data metrics. Defaults are 20 trades, PF >= 1, expectancy >= 0, Sharpe >= 0.
All failed gates are recorded, so rejection counts can overlap.

OOS only receives Validation survivors. Degradation is later/development and
later-minus-development; zero denominators or nonfinite operands produce null,
never a selection gate. Positive infinite PF is legitimate with no losses and is
serialized as the string `Infinity`; quantiles report finite observations and
nonfinite counts explicitly. All other nonfinite metrics fail closed.

## Results and portfolio

- `runs/eurusd_h1_250k_v16_validation.sqlite`: validation_runs,
  development_results, validation_results, oos_results, final_candidates.
- `runs/reports/v16_validation_summary.json`: audit, source provenance, frozen
  configuration, distributions, degradation medians, portfolio and timings.
- `runs/reports/v16_final_candidates.csv`: one row per OOS survivor, all three
  sets of requested metrics.
- `runs/reports/v16_source_verification.json`: full-data parity and historical
  artifact hashes.

Each invocation appends a distinct validation run to the output SQLite; it does
not overwrite earlier result rows. JSON/CSV paths contain the latest invocation.
No output may share a resolved path with an input. Database rows preserve source
run, strategy ID/hash, canonical definition, stage, metrics, status, all rejection
reasons, degradation and UTC timestamp.

Final eligibility requires both gates. Ordering is frozen by Development
expectancy_r, with canonical hash as deterministic tie-break. Diversity measures
absolute correlation of realized PnL aligned to the same OOS bar timestamps, and
entry timestamp overlap. This deliberately corrects the legacy portfolio's
trade-ordinal alignment. The portfolio is capped at 10 with equal weights and
never padded. An empty survivor set is a successful, empty result.

Combined return and drawdown are fractions of initial capital, with realized PnL
and an initial zero-return baseline. Combined Sharpe uses business-day realized
PnL changes and sqrt(252); individual strategy Sharpe retains the source engine's
trade-R convention. Correlation is absolute. Source execution uses price-unit
PnL, not FX lot sizing, so combined return fractions are very small. No execution
or sizing assumption was changed to improve results. Portfolio statistics are
**post-selection OOS diagnostics**, not independent validation of the portfolio.

## Future clean discovery (prepared, not run at 250K)

```bash
.venv/bin/python -m sqx_engine.cli run configs/eurusd_h1_250k_clean_v16.yaml
```

`data_split` routes only `development_df` to features, FastEvaluator, parallel
workers, genetic feedback, ranking and every discovery funnel stage. Validation
and OOS frames leave scope before those consumers are constructed. Small synthetic
Genetic runs in tests exercise this route, including evolution; no new production
search was performed for V1.6.

A dedicated discovery database stores `discovery_provenance`: dataset fingerprint,
exact split boundaries, execution configuration and configuration hash. Checkpoints
bind the same context. Full-data checkpoints cannot be resumed as clean discovery;
changing data, split or configuration also prevents checkpoint reuse. New clean
runs refuse an occupied database unless resuming the matching checkpoint.

For validation of that future completed run, copy the validation YAML, set its
source run/database/checkpoint/config, remove the historical engine override if
not applicable, update/remove expected candidate count, and set `test_type: TRUE_OOS`.
The validation engine verifies stored provenance against the dataset and split
before it accepts that label; merely changing the label is insufficient. Future
configurations should keep gates fixed before opening Validation/OOS. This records
engine-controlled exposure; it cannot certify that humans have never inspected
market data outside the engine.

## Regression coverage

Tests cover partition coverage/boundaries, invalid input, immutable definitions,
known-answer metrics and costs in both stages, survivor routing, rejection reasons,
nonfinite metrics, SQLite round-trip, empty and partial portfolios, protected
inputs, checkpoint context and verified clean provenance. The mandatory leakage
test changes all later OHLCV prices with the same seed and compares every generated
canonical definition, metric, quality score, rejection, ranking and portfolio from
a real multi-generation Development discovery run.
